No Windows, as pastas são separadas por barra invertida: C:\xampp\mysql\bin.

E, no PowerShell, um programa que está na pasta atual só roda se você escrever .\ na frente do nome dele. É a diferença que mais trava aluno. No Prompt de Comando, o .\ não é preciso.

Preparação

Passo 4 · Rodar a carga

Digite a linha inteira e aperte Enter. Ela chama o programa mysql.exe, que vem com o XAMPP, e manda ele executar o arquivo da carga.

Forma geral do comando
.\mysql.exe -u root -p -e "SOURCE C:/xampp/carga_corte_certo.sql"
Prompt de Comando
PS C:\xampp\mysql\bin> .\mysql.exe -u root -p -e "SOURCE C:/xampp/carga_corte_certo.sql"
Enter password:
PS C:\xampp\mysql\bin>
PS C:\xampp\mysql\bin>
Cada parte do comando
  • .\mysql.exe — o programa que conversa com o banco.
  • -u root — quem está entrando: o usuário root, o dono do banco.
  • -p — avisa que vem senha. O terminal mostra Enter password: e não aparece nada enquanto você digita. No XAMPP padrão o root não tem senha: aperte Enter direto.
  • -e "SOURCE ..." — manda executar o arquivo. Repare que o caminho do programa usa barra invertida e o de dentro do SOURCE usa barra normal. As duas na mesma linha estão certas: quem lê a primeira é o Windows, e quem lê a segunda é o banco.

Quando dá certo, nada aparece. O prompt volta, e pronto.

O SOURCE não para no primeiro erro

Se algo falhar no meio do arquivo, os comandos seguintes continuam e o prompt volta como se estivesse tudo certo. Por isso o passo 6 não é opcional: role a tela para cima procurando a palavra ERROR e rode a conferência.

AND e OR

AND exige que as duas condições sejam verdadeiras. OR aceita quando pelo menos uma é. Cada AND deixa o resultado menor; cada OR deixa maior.

LIKE procura por pedaço de texto. O sinal % significa "qualquer coisa, de qualquer tamanho".

2 · Procedure: pagar e fechar na mesma transação

Uma procedure é um bloco de comandos guardado no banco, com nome, que se executa com CALL. Serve para garantir que um conjunto de passos aconteça sempre igual.

Fechar uma comanda são dois passos que precisam acontecer juntos: registrar o pagamento e marcar o atendimento como pago. Se o primeiro acontecer e o segundo falhar, o studio recebe e o sistema não sabe.

O DELIMITER troca o sinal que termina o comando, para que os ponto e vírgula de dentro do corpo não encerrem a criação antes da hora.

DELIMITER $$
CREATE PROCEDURE sp_fechar_comanda(IN p_numero INT, IN p_forma VARCHAR(10))
BEGIN
  DECLARE v_valor DECIMAL(10,2);
  DECLARE EXIT HANDLER FOR SQLEXCEPTION
  BEGIN
    ROLLBACK;
    RESIGNAL;
  END;

  SELECT valor INTO v_valor FROM agendamento WHERE numero = p_numero;
  IF v_valor IS NULL OR v_valor <= 0 THEN
    SIGNAL SQLSTATE '45000' SET MESSAGE_TEXT = 'agendamento sem valor: nada a receber';
  END IF;

  START TRANSACTION;
    INSERT INTO pagamento (agendamento_id, pago_em, valor, forma)
    VALUES (p_numero, '2026-09-12 19:00:00', v_valor, p_forma);
    UPDATE agendamento SET status = 'atendido' WHERE numero = p_numero;
  COMMIT;
END$$
DELIMITER ;

CREATE FUNCTION fn_comissao_do_profissional(p_prof INT, p_mes CHAR(7))
RETURNS DECIMAL(10,2)
READS SQL DATA
BEGIN
  DECLARE v_total DECIMAL(10,2);
  DECLARE v_perc DECIMAL(5,2);
  SELECT comissao_percentual INTO v_perc FROM profissional WHERE codigo = p_prof;

  RETURN ROUND(v_total * v_perc / 100, 2);
END$$

Porque a coluna está dentro de uma função: DATE(inicio). O banco precisaria calcular DATE() em cada linha para comparar, e por isso não consegue usar o índice. A consulta devolve as mesmas linhas, e lê a tabela inteira para isso. Escrever o filtro como intervalo é o que torna o índice útil.

5 · Permissões: o usuário da recepção

Nem todo mundo precisa poder tudo. Os comandos de controle de acesso criam um usuário e dizem o que ele pode fazer: CREATE USER cria, GRANT concede, REVOKE tira.

A recepção precisa consultar e registrar. Não precisa mudar preço, e não precisa apagar nada.

O CREATE OR REPLACE evita o erro 1396 quando o exercício é repetido: o usuário não mora dentro do banco e sobrevive à carga.

Por que a recepção não recebe permissão de EXECUTE?

Porque a procedure sp_fechar_comanda roda com os poderes de quem a criou. Dando EXECUTE à recepção, ela passaria a alterar a tabela por dentro da procedure, furando a restrição que o GRANT acabou de estabelecer.

6 · Cópia de segurança e restauração

O mysqldump grava o banco inteiro num arquivo de texto, com os comandos que recriam tudo. É a cópia de segurança, e é o que se leva quando o trabalho muda de máquina.

Dois cuidados, os dois testados: a opção --databases é obrigatória, senão o arquivo não recria o banco; e a gravação usa --result-file, porque o sinal de maior, no PowerShell, grava num formato que o banco não lê de volta.

O comando abaixo não é SQL: ele roda no PowerShell, fora do banco. A saída mostra o começo do arquivo gerado.
